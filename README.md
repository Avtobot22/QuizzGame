# QuizzGame

TV-first приложение для квизов с друзьями. Телевизор — основное устройство ведущего: выбор и запуск игры, лобби, вопросы и результаты. Android-телефоны подключаются к комнате как устройства участников.

## Сценарий продукта

- TV открывается в гостевом режиме. При запуске выбранной игры проверяется, разрешён ли гостевой запуск. Если разрешён — игра запускается гостем; иначе нужен вход на самом TV, после которого продолжается выбранный запуск. Уже действующая сессия TV удовлетворяет требованию входа; отмена возвращает к выбранной игре.
- Участник сканирует QR комнаты на TV и присоединяется с телефона, обычно без регистрации. Аккаунт ведущего не обязывает участников создавать аккаунты.
- Сессии TV и телефона независимы: хозяин может войти в аккаунт на TV, а со своего телефона присоединиться гостем. Вход на телефоне не нужен для авторизации TV и запуска игры. QR комнаты даёт только права участника.

Это согласованное направление от 24.10.2026. Сейчас подготовлены точки входа приложений и дизайн-система. Пользовательские экраны, комнаты, QR-присоединение, авторизация и серверная игра пока не реализованы.

## Начало работы

1. Установить JDK 21, Android SDK Platform 37.0 и Build Tools 36.0.0.
2. Открыть папку в Android Studio с поддержкой закреплённого AGP, выбрать Gradle JDK 21. Критерий daemon также закреплён на Java 21; автоматическое скачивание JDK не настроено.
3. Указать SDK через локальный `local.properties` или `ANDROID_HOME`.
4. Выполнить `./gradlew qualityCheck` и запустить `:app:tv` на Android TV либо `:app:mobile` на телефоне.

Минимальная версия Android — API 26. Версии библиотек и плагинов закреплены в `gradle/libs.versions.toml`, Gradle — в wrapper. В Windows используется `gradlew.bat`.

## Структура и границы

| Путь | Назначение |
|---|---|
| `app/tv` | Основное TV-приложение, управление с пульта |
| `app/mobile` | Приложение входящего участника |
| `core/ui` | Общие токены, игровые цвета, Roboto и ресурсы |
| `core/designsystem/mobile` | Mobile Material 3: светлая/тёмная темы и компоненты Quizz |
| `core/designsystem/tv` | TV Material: тёмная тема, состояния ответа и компоненты с D-pad-фокусом |
| `gradle` | Version catalog, wrapper и критерий JVM |
| `buildSrc` | Convention plugins: Mobile/TV приложения, общие и платформенные библиотеки |
| `config/detekt` | Правила анализа и форматирования Kotlin |
| `.github` | CI, обновления зависимостей, шаблоны задач и PR |

Feature владеет своим вертикальным срезом: UI/presentation, нужными domain-правилами и собственным data-слоем. Репозитории, DTO, мапперы и storage остаются внутри неё, пока другие фичи ими не пользуются. Границы пакетов внутри фичи не требуют отдельных Gradle-модулей для каждого слоя.

При появлении нескольких реальных feature-потребителей общая предметная возможность выделяется в `shared:<capability>` с необходимыми domain/data частями. Два app entry points, использующие одну и ту же feature, сами по себе не требуют такого переноса. `core` предназначен для низкоуровневой инфраструктуры; общие бизнес-репозитории не складываются в него без предметной границы.

Domain остаётся чистым Kotlin; data реализует его контракты. App собирает реализации и навигацию. Фичи не зависят от внутренних реализаций друг друга. Новые Gradle-модули добавляются вместе с реальными сценариями. Телефон использует Material 3, TV — TV Material с отдельным фокусом и D-pad-вводом.

Сборочные файлы модулей подключают `quizz.android.mobile.application`, `quizz.android.tv.application`, `quizz.android.shared.library`, `quizz.android.mobile.library` или `quizz.android.tv.library`. SDK, JVM, Compose, lint и базовые тестовые зависимости настраиваются в `buildSrc`. Межмодульные зависимости типизированы: `implementation(projects.core.designsystem.mobile)`, `api(projects.core.ui)`. Enum-константы используют `UPPER_SNAKE_CASE`; это проверяет Detekt.

## Дизайн-система

Источник — [Quizz Material 3: Foundations, Mobile Components, TV Components](https://www.figma.com/design/MF04FtAWBhvcGZpYrHQV7g/Quizz-Android?node-id=0-1), локальная копия от 24.10.2026. В код перенесены полная брендовая tonal palette, семантические цвета тем, игровые цвета, Roboto, размеры и формы компонентов. Полные выгрузки и архивные значения остаются в локальных исходных материалах.

Телефон оборачивает контент в `QuizzMobileTheme`, TV — в `QuizzTvTheme`. Стандартные элементы берутся из соответствующего Material; собственные OTP, код комнаты, TV-карточка ответа и панель статуса находятся в платформенном модуле дизайн-системы. Игровые цвета доступны через `LocalQuizzGameColors`; это роли представления, а не правила определения правильного ответа.

Экраны используют `MaterialTheme` своей платформы и семантические роли. Все цвета Material-тем заданы явно через брендовые тона; палитра и привязки меняются в Kotlin, без HEX в экранах. Фокус TV отличается от выбранного ответа; QR, код и таймер остаются нефокусируемым контентом. Панель из дизайна с историческим именем `PairingPanel` не добавляет обязательное спаривание или вход на телефоне.

## Проверки

```sh
./gradlew qualityCheck
./gradlew :app:mobile:connectedDebugAndroidTest
./gradlew :app:tv:connectedDebugAndroidTest
```

`qualityCheck` выполняет Detekt с проверкой форматирования, lint, unit-test tasks, debug/release-сборки и компиляцию instrumentation APK. Lint warnings считаются ошибками; advisory о более новых версиях сборочных инструментов остаётся информационным. Unit-test task без тестовых файлов может завершиться `NO-SOURCE`.

Connected-тесты запускаются отдельно на устройстве соответствующей платформы. Проверяй сохранение состояния, D-pad, видимый фокус и Back; для UI также нужны ручные проверки крупного шрифта и доступности. Release собирается с R8, production signing и публикация не настроены.

Отчёты находятся в `build/reports/`, `app/*/build/reports/` и `core/**/build/reports/`. Debug APK — в `app/*/build/outputs/apk/debug/`.

## Локальные материалы и Git

Папка `docs/` содержит продуктовые уточнения, исходники и архитектурные решения. Сейчас она целиком исключена через `.git/info/exclude` только в этой рабочей копии. При клонировании репозитория эти материалы не появятся. Основные правила разработки приведены в этом README, а проверка CI не зависит от локальных документов.

Initial commit создан на `chore/bootstrap`, из него сформирована первая ссылка `main` пустого репозитория. Последующие изменения проходят через отдельные ветки и PR; прямые коммиты и push в `main` не используются. CI выполняет `repository-check`, Dependabot обновляет зависимости. Активная защита `main` требует PR, закрытых review threads и успешной проверки; force push и удаление ветки запрещены. PR сливаются через squash.
